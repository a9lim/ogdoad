# Counterexample search and random model for the `0/1/4` excess rule

Parked research material for `docs/OPEN.md` §2. Nothing here proves or
refutes the rule. The table rows are *implemented and tested* (exact,
replayable computations); the mathematical results under "Theory" are
*proved here* at the stated review level and are not yet in
`writeups/excess.tex`.

## Why a search

Every odd prime `p` is exactly one row of the rule. If the selected Conway
element of a row behaves like a uniform element of its cyclic group, the row
fails (the rule translate is a `p`-th power) with probability `1/p`. The sum of
`1/p` diverges, so in that **random model** the rule fails infinitely often,
roughly `log log X` times below `X`, while `sup m_p` stays finite. The model
is a heuristic about the tower, not evidence of a failure. The analogous
Wieferich-type heuristics have mixed calibration; Wall–Sun–Sun primes in
particular undershoot it.

Under the model, the rows tested so far (OEIS to 709, Peeters' records to
12,281, and this directory's rows) obey the rule with model probability about
0.3. The untested mass below `10^5` is about 0.28.

## Engines

- `census.py` computes `f(p)`, DiMuro's `Q(h)`, the arm, the rule value, and
  `E(p)`. It reproduces all 126 OEIS rows. Usage: `python3 census.py N`.
- `ref/` is the reference engine. `refengine.cpp` builds one sparse model of
  `F_(2^E)` and embeds the components in dependency order by exact
  Artin–Schreier and Adleman–Manders–Miller roots. Each root is checked
  (`y^ell == a`, exact degree), then the Euler test runs.
  - Canonicity: the term algebra is a field, so any root choice gives the same
    answer. Shared ancestors are one element.
  - Limited to `E` of a few `10^4` because of NTL's `BuildSparseIrred`.
  - `rowprog.py` emits a row's component program, `search_ref.py` is the
    dependency-aware driver (hits are written first to `HITS.jsonl`), and
    `validate.py` checks against OEIS.
- `v2/` is the crossed-binomial engine (`v2/README.md`). It has three paths:
  - singleton tops (arms O/C/D), via Codex's crossing of the 719
    certificate;
  - two-component arm-Z ratio rows, `beta = y2 (1 + y1/y2)`;
  - one-odd-plus-finite rows.

  It runs a norm-first Euler test with a cyclotomic split. Its limits are
  parent fields with `B > 6e4` (sparse modulus), zero-arm rows with three or
  more components, inherited levels, and the conda gf2x without PMULL.

Build both engines against NTL and gf2x, e.g. from a micromamba env with
`ntl gf2x gmp`:
`clang++ -O3 -std=c++17 -I$ENV/include refengine.cpp -L$ENV/lib -lntl -lgf2x -lgmp -Wl,-rpath,$ENV/lib`.
`rows_1000000.pkl` is not committed; it is regenerated by `census.py`.

## Where to pick up: `notes/V3_PLAN.md`

The reviewed plan has these milestones:
- **M0**: safety-net driver.
- **M1**: hardened engine on the PMULL/PCLMUL multipliers.
- **M1b**: independent `mu` cross-validation through the dual builder.
- **M3–M5**: single-big-component path, compact Euler stage, tensor parent
  fields.

It stops for a decision at 100, 300 and 1000 core-hours. Its honest yield is
about 3–6% at 100 core-hours and about 5–11% at 1000 core-hours (discounted by
the clean record). The certain deliverable is an exact excess table well past
709.

Two decisions from the review:
- The canonical row record is `mu`, the minimal polynomial over F_2 of the
  norm to `F_(2^h)`.
- A failure found while assuming the rule for ancestor rows already refutes
  the rule (at that row or an ancestor), so the search can run in any order.

The hit-certification protocol (Levels 0–5) is in §5 of the plan.

## Theory produced alongside (proved here; not yet in the paper)

- **Random model and Lean.** `formal/Ogdoad/ExcessRandomModel.lean` proves
  that independent `1/p` events over odd primes occur infinitely often almost
  surely, along with the expected-count formula. The statement is about the
  model only.
  - The full model section, refereed, is
    `notes/random_model_section_reviewed.tex`.
  - The matching `docs/OPEN.md` patch is `notes/open_md_patch_reviewed.md`.
- **Arms C and D are cyclotomic-unit statements.** `kappa_(3^k)` is a primitive
  `3^(k+1)`-th root of unity, and 2 is inert in `K = Q(zeta_(3^(k+1)))^+`.
  - An arm-C row fails iff the `psi`-part of `Cl(K)_p` is nonzero, or `2O_K`
    splits completely in `K(mu_p, E_K^(1/p))`.
  - Arm D has the same statement in `Q(zeta_(5*3^(k+1)))^+`.
  - Status: proved by an agent and adversarially checked by Codex (verdict:
    core correct, fixable; corrected statement in
    `notes/codex_theoremC_and_D.md`).
- **Translate ties (exact).** These come from automorphisms that move `kappa`
  itself.
  - In arm-Z rows whose `Q(f(p))` contains a 2-power, `Frob^(E/2)` sends
    `kappa` to `kappa + 1`, so `m_p` is never 1 or 3. These rows also carry a
    generalized Fermat-torus coordinate.
  - In arms C and D, all twelve translates by nimbers 4..15 share their
    power status. So an arm-D failure forces `m_p >= 16`, and an arm-C row that
    fails twice also gives `m_p >= 16`.
  - See `notes/heuristic_numbertheory_critique.md` and the Codex note.
- **Cell-success lemma.** Every arm-O cell whose rows contain no base-2
  Wieferich prime has a row obeying the rule.
- **Nonconstructive route: obstruction.** Homogeneous multiplicative relations
  cannot force a failure; a relation-based failure proof would itself exhibit
  the failure. Averaging tools (Weil, Chebotarev, Katz) work below the
  square-root threshold for a single selected orbit. The problem has the
  shape of Wieferich infinitude, but no reduction to it is known in either
  direction. See `notes/heuristic_nonconstructive.md`.
- **Control family.** Gaussian periods `zeta + zeta^-1` are cubes more often
  than `1/3`, through a class-number channel. Natural selected elements lean
  *toward* being powers.
